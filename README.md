# Кассовый контроль — ForteBank Cash Desk AI

**Datathon 26 · AI-сервис для выявления нарушений кассовой дисциплины по видео**

`Qwen3-VL-8B` · `LoRA (PEFT)` · `RT-DETR v2` · `Правила по нормативам НБРК` · `Ensemble` · `FastAPI` · `100 % локально` · `Apache 2.0`

Проверяющий загружает видео работы кассира — сервис находит визуально наблюдаемые признаки возможных нарушений
и по каждому показывает **тип, таймкод, 1–3 кадра-доказательства, понятное описание и пункт нормативного акта РК**.
Все модели работают на одной GPU внутри сервиса, без облачных API. Результат — подсказка проверяющему,
а не юридическое заключение.

---

## 🌟 Коротко о главном

| | |
|---|---|
| **Гибридная ML-система** | Мультимодальная модель отвечает на 18 вопросов «да/нет» о каждом кадре, детектор находит предметы, дообученная LoRA ищет нарушения по окнам видео — ансамбль объединяет ответы |
| **Модель видит — правила решают** | Нарушение собирается кодом по визуальным критериям из нормативов, поэтому каждое срабатывание объяснимо: правило + длительность + пункт закона |
| **Только реальные законы** | Ссылки берутся только из базы `rules/norms.yaml`: 2 акта НБРК, 30 пунктов с дословными цитатами, сверены на adilet.zan.kz |
| **Честные формулировки** | «Может указывать на нарушение п. X», ничего о невидимом (суммы, проводки), без распознавания лиц |
| **Готовый продукт** | Веб-интерфейс с плеером для аудита, прогрессом по этапам модели, PDF-отчётом, историей и обратной связью |
| **Человек в контуре** | Кнопки «Верно / Неверно / Модель пропустила» копят датасет для регулярного дообучения |
| **Готов к контуру банка** | Только лицензии с коммерческим использованием, `HF_HUB_OFFLINE=1`, одна GPU 48 ГБ, ~20–60 с на видео (лимит 5 мин) |

```
 Браузер (UI)  или  внешний клиент API
        │   X-API-Key
        ▼
 ┌──────────────────────────── GPU-сервер ────────────────────────────┐
 │                                                                    │
 │  Бэкенд  (backend/, FastAPI, порт 8000)                            │
 │   • API строго по ТЗ: POST /api/v1/analyze → GET /api/v1/jobs/{id} │
 │   • очередь задач, вырезка участка / зоны кассы (ffmpeg)           │
 │   • норма и цитата — только из rules/norms.yaml                    │
 │   • веб-интерфейс (frontend/), отзывы → storage/feedback/          │
 │        │  POST /infer_async  +  GET /progress/{id}   (X-ML-Token)  │
 │        ▼                                                           │
 │  ML-сервер  (ml/, порт 8001)                                       │
 │   • Qwen3-VL-8B + LoRA + RT-DETR v2 + правила → ансамбль           │
 │                                                                    │
 └────────────────────────────────────────────────────────────────────┘
```

Бэкенд и ML-сервер работают на одной машине и общаются через `localhost` — видео не покидает сервер
на пути к моделям. Наружу открыт только порт 8000 (UI + API).

### ML-пайплайн

```
видео .mov
  │
  ├─ кадры с точным временем (OpenCV, 2 кадра/с; время из видео — FPS «плавает», 29.92)
  │
  ├─ [1] Qwen3-VL-8B (без адаптера)
  │      • роли людей по 8 кадрам из всего видео (кассир / клиент / инкассатор — по положению и одежде)
  │      • 18 вопросов да/нет к каждому кадру (1 кадр/с, увеличение ×1.5, пакеты по 8)
  │
  ├─ [2] Детектор предметов RT-DETR v2 (19 классов)
  │      • заменяет ответы Qwen на «предметные» вопросы: деньги, ключи, печать, сейф, дверь, удостоверение, сумка
  │
  ├─ [3] Правила по критериям нормативов (rules.py)
  │      • интервалы с порогом длительности, фильтр «фона сцены», требование появления события
  │
  ├─ [4] Qwen3-VL-8B + LoRA-адаптер: окна 8 с → {"violations": [{"id": "V14", "time_sec": 18}]}
  │
  └─ [5] Ансамбль (suppress_near) → шаблон описания + норма → кадры-доказательства (base64)
                                                          ↓
                                          JSON в формате ТЗ (раздел 10)
```

Исходная модель и LoRA-версия живут в **одной** загруженной модели: для вопросов по кадрам адаптер временно
выключается (`disable_adapter`), для поиска нарушений — включается.

## 🔌 API

Доступ по ключу в заголовке `X-API-Key` (без верного ключа — `401`). Формат ответа строго по ТЗ.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/v1/analyze` | Загрузить видео `.mov` (поле `file`) → `{"job_id": "..."}` |
| `GET` | `/api/v1/jobs/{job_id}` | Статус `processing` / `done` / `failed` и результат |

```bash
curl -X POST https://<адрес-сервиса>/api/v1/analyze -H "X-API-Key: <ключ>" -F "file=@video.mov"
curl https://<адрес-сервиса>/api/v1/jobs/<job_id> -H "X-API-Key: <ключ>"
```

```json
{
  "job_id": "3f2a9c1e",
  "status": "done",
  "verdict": "violation",
  "violations": [
    {
      "type": "Наличные оставлены без присмотра",
      "timecode_sec": 44.2,
      "description": "Что видно на видео и почему это может указывать на нарушение",
      "evidence_frames": [{ "timestamp_sec": 44.2, "image_base64": "/9j/4AAQ..." }]
    }
  ]
}
```

Если ML-сервер не ответил за 280 с, задача получает `failed` — чтобы уложиться в лимит 5 минут.

## 🧠 ML-часть

### Как мы пришли к решению (каждый шаг — с цифрами)

| Шаг | Подход | Результат на датасете | Вывод |
|---|---|---|---|
| 1 | VLM сама выбирает нарушение из списка по окну 10 с | вердикт **50 %**, 18 пропусков | модель видит сцену, но не знает, что считать нарушением |
| 2 | Двухэтапный: VLM описывает окна → та же VLM ищет нарушения в описании | без улучшения | роли «скачут» между окнами |
| 3 | + определение ролей один раз на видео | роли стабильны, нарушения всё равно мимо | мелкие действия рук VLM видит нестабильно |
| 4 | **Checklist**: 18 вопросов да/нет к кадру + правила | 23/26 найдено, но **15 ложных** из 16 чистых | правила верны, часть вопросов — шум |
| 5 | Анализ по типам (`fp_report.py`) → отключение шумных правил | ложных **0**, ~69 % | «телефон» Qwen путала с калькулятором |
| 6 | Дообучение LoRA, проверка на отложенных видео | LoRA одна: 1 из 5 найдено, но тип точный | мало данных → модель осторожна |
| 7 | **Ensemble** (checklist + LoRA) | на новых видео 3 из 5 найдено, 0 ложных | части ошибаются по-разному |
| 8 | + **детектор предметов** на нашей разметке | **75 %**, полнота по типам 31 % → 41 % | предметы — главная слабость VLM |
| 9 | Финальная эпоха детектора | **78 %**, полнота 48 % | |
| 10 | Офлайн-подбор порогов (`tune.py`, 864 варианта) | **82 %**, ложных 1, полнота 55 % | дверь «оставлена открытой» = ≥ 10 с |
| 11 | Исправление V12 по своим видео (документ на столе = предъявлен) | 80 % на датасете, +1 на своих видео | правило стало верным по смыслу |

### Техники

**Мультимодальная модель (VQA + правила)**
- Структурированные вопросы вместо классификации: ответ строго JSON с ключами и 0/1, разбор устойчив к лишнему тексту.
- Роли людей один раз на видео по 8 кадрам из всего ролика — без распознавания лиц.
- Увеличение кадров ×1.5 для мелких предметов; видео 1080p уменьшаются до 960 px, чтобы уложиться во время.
- Пакетная обработка (8 кадров за вызов) с автоматическим переходом на поштучную при нехватке памяти.

**Правила (rule engine)**
- Интервалы с порогом длительности и допуском пропусков (пропуск 1 кадра не рвёт интервал) — аналог гистерезиса.
- Фильтр фона сцены: состояние, видимое с первого кадра и на > 70 % кадров, — предмет интерьера или постоянная ошибка модели, а не событие.
- Сессии клиента для операционных нарушений (V12: операция с деньгами, документ за всё время не виден).
- Ограничения повторов: не больше одного V15/V16/V19 на видео, до 5 нарушений на видео.

**Дообучение Qwen3-VL методом LoRA**

| Параметр | Значение |
|---|---|
| Метод | PEFT / LoRA: ранг 16, alpha 32, dropout 0.05 |
| Что обучается | только языковая часть (q, k, v, o, gate, up, down); визуальный энкодер заморожен |
| Объём | 43,6 млн параметров из 8,8 млрд (**0,5 %**), адаптер ~170 МБ |
| Данные | окна 8 с (8 кадров с подписанным временем), сдвиг 2 с → 315 примеров (105 с нарушением, 210 без); окна на границе нарушения исключены |
| Обучение | 3 эпохи, lr 1e-4 с прогревом, 8 примеров на шаг, gradient checkpointing, loss только на ответе модели |
| Валидация | 34 видео + 8 отложенных (честная проверка), затем финальное обучение на всех |

**Детектор предметов RT-DETR v2 (transfer learning)**
- База `PekingU/rtdetr_v2_r50vd` (COCO), новая голова под 19 классов; аугментации: отражение, яркость.
- Лучшая эпоха по среднему F1 на проверочной части — итог **F1 0,79**.

| Класс | Точность / полнота |
|---|---|
| сейф открыт | 0,98 / 1,00 |
| дверь открыта | 0,90 / 0,88 |
| деньги | 0,70 / 0,75 |
| печать | 0,68 / 0,93 |
| ключи | 0,51 / 0,56 |

- Порог применяется при подстановке, а не при детекции: в кэш пишутся рамки от 0,3 → пороги подбираются без модели.
- Детектор заменяет флаг Qwen только для классов, на которых обучен.

### Данные: что дали организаторы и что мы собрали сами

| Набор | Объём | Как получен |
|---|---|---|
| Видео организаторов | 42 видео (2 дубликата найдены по md5: X-47 = X-4, X-48 = X-5) | датасет хакатона |
| Разметка аналитиков команды | 26 видео с нарушениями, 14 типов, пункты норм | просмотр всех видео + нормативы РК |
| Разметка предметов | ~2500 кадров, 19 классов | разметили сами |
| Разметка людей и действий | 426 кадров, 728 рамок | команда, локально в Label Studio |
| Собственные видео | 4 видео, другой ракурс, разыгранные нарушения и чистые операции | сняли сами |

**Почему собирали свои данные.** Датасет маленький (у большинства типов 1–2 примера), а разметка предметов дала
детектору тысячи примеров того, что VLM видит плохо. Финальное видео проверки снято под другим углом — проверить это
можно только на видео, которые никто не видел при настройке: свои видео нашли две реальные проблемы
(V12 и детектор людей), обе исправлены или компонент отключён. Все данные хранятся только у команды и на сервере.

## ⚖️ Нормативная база

| Документ | Пунктов |
|---|---|
| Правила № 231 — кассовые операции и инкассация (постановление Правления НБРК от 29.11.2019) | 26 |
| Правила № 14 — охрана и устройство помещений банков (постановление Правления НБРК от 24.02.2020) | 4 |

- Каждый пункт — дословная цитата, ссылка на adilet.zan.kz и дата сверки (`rules/norms.yaml`).
- Связь «пункт → тип нарушения» — в `rules/violation_types.yaml` (28 типов: визуальный критерий, нормы, шаблон описания;
  невидимые по видео случаи вынесены в `excluded`).
- Ссылки в ответе берутся **только** из этой базы; модель не генерирует номера пунктов.

## ⚠️ Ограничения

- **Другой ракурс — главный риск.** Детектор и правила настраивались на одной камере; на новом ракурсе качество ниже.
- **Подгонка под датасет.** Правила и пороги подбирались по тем же 40 видео — реальная точность на новых видео ниже 80 %.
- **Процедурные нарушения** (выдача / приём без пересчёта — V05, V06, V08, V28) почти не находятся: нужна
  последовательность действий рук, а кадры раз в секунду этого не дают.
- **Телефон кассира (V01)** не распознаётся: мало примеров в разметке (полнота детектора 8 %), правило отключено.
- **V16 (посторонний)** даёт ложные срабатывания при нескольких клиентах и необычном ракурсе.
- **V12** зависит от того, виден ли документ в кадре. **V26** (посторонние наличные) отключён из-за ложных срабатываний.
- **LoRA** точна, но осторожна — упирается в объём данных, а не в метод.
- **Зона кассы (ROI)** в интерфейсе экспериментальная: модели обучались на полных кадрах.

### Что пробовали и отказались

| Идея | Почему нет |
|---|---|
| VLM сама классифицирует нарушение | 50 % — уровень монетки |
| YOLO (Ultralytics) | лицензия AGPL несовместима с коммерческим использованием → RT-DETR (Apache 2.0) |
| Детектор людей и действий | F1 0,81 на знакомом ракурсе, но ложный V16 на всех своих видео с нового ракурса |
| Генерация видео ИИ для обучения | разрыв доменов, сложно управлять деталями, риск по правилам о данных |
| Шаг окон LoRA 2 с | без прироста, + время |

## 🚀 Запуск

### Локально (интерфейс и API)

```bash
python3.11 -m venv .venv && source .venv/bin/activate   # Python 3.11
pip install -r backend/requirements.txt
cp .env.example .env                                     # API_KEY, ML_URL, ML_TOKEN
cd backend && uvicorn main:app --reload                  # http://localhost:8000   (?demo — пример без ML)
```

Без `ML_URL` работает запасной локальный пайплайн-заглушка (`backend/pipeline/model.py`) — удобно для разработки UI.

### На GPU-сервере (как развёрнуто)

```bash
# 1. ML-сервер (порт 8001); один раз до этого: bash ml/src/setup_server.sh
cd /workspace/datathon
export ML_TOKEN=$(cat ml_token.txt)
HF_HUB_OFFLINE=1 nohup uvicorn ml_server:app --app-dir src --host 0.0.0.0 --port 8001 > ml_server.log 2>&1 &

# 2. Бэкенд + интерфейс (порт 8000); в .env: ML_URL=http://localhost:8001 и тот же ML_TOKEN
cd /workspace/DAteam/backend
nohup ../.venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000 > ../backend.log 2>&1 &

# 3. Публичный адрес: туннель на http://localhost:8000
```

Docker: `docker compose up --build` · Тесты API: `pytest tests`

## 🔭 Развитие

- **Активное обучение:** отзывы проверяющих («Верно / Неверно / Пропущено») → новая разметка → регулярное дообучение LoRA.
- **Разметка с нескольких камер** → детектор людей и действий → V05 / V06 / V08 / V28 и устойчивость к ракурсу.
- Дообучение визуальной части модели при большем объёме данных.
- Правило «рабочее место оставлено с включённым компьютером» (детектор уже различает включённый ноутбук, F1 0,92) —
  после согласования с регламентом ИБ банка.
